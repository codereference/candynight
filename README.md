# Sweet Nights Tycoon

A cute bakery and candy shop tycoon for Roblox that takes light, spooky turns at night.

- **By day**, serve NPC customers, unlock better treats, décor and staff, and grow your shop with expansion packs.
- **By night**, shadow creatures come out. Protect your customers with automatic defenses and handheld weapons, or sneak into rival shops and steal their cash.

Kid-friendly (Roblox **Mild** maturity), and built for mobile and PC.

## Status

Feature-complete and ready for playtesting. The design is in the spec, [#1](https://github.com/codereference/candynight/issues/1). The steps that need the owner's Roblox account (ids, uploads, publishing) are in [docs/launch-checklist.md](docs/launch-checklist.md).

## Features

- 6 players per server, each with their own shop plot
- Customers to serve, staff to hire, a tree of buy buttons to unlock, and expansion packs
- Grid placement for defenses, which have health and can be destroyed
- Day/night cycle, with nights that get harder as you go
- A survival streak, which resets if you lose too many customers in one night
- Night-only raiding, where an invader killed by the defender is locked out until the next night
- Saved progress, rebirth multipliers, capped offline earnings, a leaderboard and badges
- Daily login rewards, codes, group and friend bonuses, and limited-time events
- Gamepasses, defense-boost dev products and free private servers

## Tech

- **Roblox / Luau**, synced into Studio with [Rojo](https://rojo.space)
- **Pure rules layer:** all game rules live in Luau modules that don't touch the Roblox engine. They're tested headless with [Lune](https://github.com/lune-org/lune). Thin adapters connect those rules to the Roblox world, which is checked by playtesting in Studio.
- **Server-authoritative:** cash, damage and saving all happen on the server.
- **Art:** low-poly meshes generated by Blender Python scripts.

## Development

Tools (Rojo, Lune, StyLua, luau-lsp) are pinned in `rokit.toml`. Install them with:

```bash
rokit install
```

**Play in Studio:** start the sync server, open a new Baseplate place in Roblox Studio, click **Connect** in the Rojo plugin, then press Play.

```bash
rojo serve
```

**Run the tests** (headless, no Studio needed):

```bash
lune run tests/run
```

**Format:**

```bash
stylua src tests
```

**Run every check** (tests, formatting, Rojo build, luau-lsp type analysis):

```bash
scripts/check.sh
```

### Art: low-poly meshes

`blender/generate_meshes.py` builds every mesh from code and exports single-colour OBJ files to
`assets/meshes/`, plus `src/shared/MeshSizes.luau` (each mesh's native size). Regenerate with:

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b --python blender/generate_meshes.py
```

Roblox can't load mesh files at runtime, so each OBJ has to be uploaded once:

1. In Studio, open **Asset Manager → Bulk Import** and select everything in `assets/meshes/`.
2. Right-click each imported mesh and choose **Copy Asset ID**.
3. Paste each id into `Meshes` in `src/shared/Config.luau`.

Until an id is set, the game keeps its placeholder parts, so nothing breaks while you go.

### Layout

- `src/shared/Rules/`: pure game rules (no Roblox APIs), covered by `tests/*.spec.luau`
- `src/shared/Config.luau`: every tunable number
- `src/server/`: thin server adapters that build the world and feed input and time into the rules
- `src/client/`: UI that only displays server-owned state
